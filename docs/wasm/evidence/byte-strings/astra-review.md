**Correctness and design assessment.** The following conclusions come from source inspection and the saved evidence, not new execution.

- String construction in [wasm_arrays.h](/tmp/goose-wasm-byte-strings-review-20261107/source/src/wasm_arrays.h:57) follows the existing owner and layout rules. Fixed and statically limited arrays use Memory 0; variable arrays store their length prefix in their assigned data memory; growable arrays store packed base and length in a Memory 0 header. The checker validates exact fixed length and limited capacity in `StrLit::Check`. Shared `LenStore` selects the limited prefix width from capacity. This explains why the new initializer does not repeat the fill initializer's static-capacity check.
- The byte count is checked before conversion to u32. Variable prefix plus payload fits memory32, and a narrow prefix must hold the count. Reservation checks the old top plus requested bytes in i64 and publishes the top only after growth succeeds. Adding the prefix after that reservation cannot carry into the packed memory identity. Static-data insertion also checks its memory32 limit. Empty values still get the required header or prefix; they skip the bulk copy. Local data owners register restoration, while globals retain their storage.
- Each nonempty construction uses a static Memory 0 byte source and copies into independent owner storage. Repeated literal text is not shared as mutable storage. Known destinations use `memory.copy` directly. The cached [CopyFromFrame helper](/tmp/goose-wasm-byte-strings-review-20261107/source/src/wasm_memory.h:128) selects the high u32 identity, covers Memory 0 and each data memory, and traps on an invalid selector before copying. The runtime tests cover all three test memories, zero length at the boundary, invalid identities, source/destination bounds, and unchanged destination bytes on failure in both engines.
- Native `B_PRINT` renders arguments in order into a line builder, then writes the completed line once. [SnapshotByteArgument](/tmp/goose-wasm-byte-strings-review-20261107/source/src/wasm_codegen.h:474) evaluates and captures a byte argument before the next argument. The Node adapter copies a view of the selected memory; it does not retain that view as the snapshot. Python stores immutable bytes. Later element mutation, reference rebinding, or memory growth therefore cannot change a captured snapshot. Saved output proves mutation and growth behavior for the fixture cases.
- The byte-reference loop keeps a null flag across all reference levels. Once set, it skips further loads, including stale temporary values from a previous loop iteration. It snapshots `null` instead of reading an array header. Known inline layouts stay in Memory 0; indirect variable/growable paths derive the memory from their packed address. Valid array lengths fit memory32 before the host call narrows the length to i32. This depends on valid guest values, not externally corrupted headers.
- A successful capture registers a cleanup action. Normal printing transfers each snapshot to the pending line and removes only actions with that print's unique compiler ID. A later argument's return, break, or continue emits cleanup for exited scopes. An inner exit that returns a value to an outer print leaves the outer scope's captures intact. Inlined and early-block exits use the same scope-depth mechanism. Out-of-line nonlocal return remains an explicit unsupported case. Deferred bodies use their own scopes; the checker forbids returns that leave a defer body. No new path was found that consumes a valid snapshot twice or omits a required drop.
- The Node map is lazy and per instance. Normal transfer and drop delete entries; `run()` clears both maps on terminal success or failure. A completed line owns transferred buffers until output finishes. The Python map is also lazy and local to `execute`; normal completion asserts both maps are empty. Python has no explicit exceptional-path `finally` clear. Its command-line adapter terminates on failure, so this is not evidence of a persistent leak under the tested contract. Reuse with retained exception tracebacks was not tested.
- Both adapters normalize memory32 fields and use subtraction-based bounds checks. Invalid snapshot handles fail before transfer/drop. The new snapshot counter fails at its signed-i32 limit; it counts lifetime captures, not live entries, and is not recycled. No handle-wrap test was saved.
- [Storage planning](/tmp/goose-wasm-byte-strings-review-20261107/source/src/wasm_storage.h:74) selects the three optional imports before function indices are assigned. Its walk includes live bodies, arguments, inlined function-value bodies, defaults, globals, and deferred bodies. The saved construction module needs no snapshot imports. The printing module has all three. The old scalar import set and all 72 prior module bytes are unchanged. Native/shared source is unchanged.

**Footprint assessment.** The implementation avoids per-byte AST expansion. It does not establish minimum memory use or a speed gain.

For a literal of B bytes, module data and guest copy work grow with B. Compiler string insertion and module serialization also copy data. Identical literal occurrences are not deduplicated by `WasmModule::Data`. A live constructed value has both static source bytes and its owned payload, plus its layout header/prefix and page capacity. Restoring a stack top permits reuse; it does not shrink a Wasm memory or prove that the host returns physical pages.

The dynamic copy helper is emitted once per module. Its code and branch table grow with the number of memories, limited here to 65 total memories. It uses no declared locals or guest heap. The string initializer's temporary local count does not grow with literal byte length. Existing fixed-slot/frame and data-stack allocations still apply.

For a byte argument of B bytes, host snapshot work and retained byte storage are O(B). Node makes a byte copy at capture and later copies line pieces into `Buffer.concat`. Small buffers may use the host's pool; exact allocation counts were not measured. Python `Memory.read` plus conversion to `bytes`, then line join and newline addition, can make more copies. No lower-copy or minimum-allocation claim is supported. Live snapshot storage grows with the sum of captured arguments awaiting completion, including outer prints while nested calls run. Empty and null arguments still use handles and host bookkeeping. Map entry deletion bounds logical ownership; it does not measure allocator retention or RSS.

Compiler work also grows with print argument count and reference depth. Each byte print scans its current cleanup-action vector to erase its actions. P prints with A retained actions can therefore require O(P*A) scan work. Cleanup already copies action lists to permit nested code emission; snapshots add entries while arguments are pending. Many deferred actions or nested prints can increase that work. The emitted code/local count grows with argument count, reference depth, and emitted exit/defer copies. There is no scan of a compiler cleanup list at guest runtime. No compiler CPU, heap, or scaling sample establishes whether the scan cost matters in practice.

**Unverified risks and coverage gaps.** These are not confirmed defects.

- The byte fixture covers one nullable reference level. It does not directly test deeper nullable chains, null/non-null transitions at one emitted loop site, or a no-data-memory module that prints only fixed/limited byte arrays. Add focused cases with exact expected bytes and owner checks.
- Mutation and growth during a print are covered. Same-print rebinding to a different owner, shrink/clear followed by reuse, printing through array-reference elements, and printing a returned borrowed byte reference are not directly covered by the new fixture. Existing reference tests and source inspection do not replace byte-capture checks for these combinations.
- The fixture covers ordinary nested output, an outer live snapshot, direct return, inlined return, defer output, continue, and break. It does not directly combine nested byte snapshots with an inner early exit, an inlined nonlocal return through multiple enclosing prints, or a value-producing early/loop exit that must preserve an outer capture. Add tests that distinguish the surviving owner's handles from handles that must be dropped.
- `wasm_bytes.mjs` observes maps while the guest is active, before terminal cleanup. This is useful evidence. The full harness rejects missing-drop and alias-snapshot controls for their exact reasons at both optimization levels. Individual control stdout/stderr/status files were not saved; the frozen harness and aggregate result are the available evidence. The division-by-zero case proves no partial output and the intended failure, but does not directly inspect exceptional-path map state.
- Bulk-copy failure coverage does not directly test the host snapshot ABI's invalid memory identities, out-of-range reads, duplicate consumption, invalid print tokens, or exhausted handles. Source checks appear sound. Small handcrafted ABI modules would provide direct evidence for both adapters.
- String cases include default/u16 variable prefixes, fixed, limited, both growable forms, empty values, globals, independent mutation, and large payloads. Not every explicit u8/u32/u64 prefix or limited-prefix width boundary has a direct new string case. Existing shared-layout tests provide partial support only.
- No controlled runtime samples, compiler CPU/RSS samples, host/guest allocation counts, copy-volume samples, JIT-code size, process residency, or load-scaling measurements were taken. Cleanup scans, many arguments, repeated prints, and large captures need a later coordinated measurement window. The evidence is Linux x86-64 only, with reported Node 24.22.2, wasm-tools 1.262.0, and Wasmtime Python 49.0.0. No other platform or architecture runtime claim is supported.
- This stage has native oracles and exact native-C comparisons, but no fresh full native project baseline suite. Earlier native-suite and TinyCC packaging repair results are separate evidence and were not used as new validation here.

**Unsupported or invalid inputs.** Varint prefixes, runtime-capacity limited layouts, slices as general runtime values, compound elements, whole-array copy/assignment, general array result destinations, pool owners, and out-of-line nonlocal returns remain outside the admitted Wasm lowering. Wrong fixed lengths and over-capacity limited literals are checker errors. Corrupted headers, forged packed addresses, and invalid host handles are not valid checked-language inputs. These cases must not be reported as new valid-input failures without first establishing reachability and expected behavior.
