1. **P2, test coverage: the Node completion assertion cannot detect a retained print owner.** The assertion is at [test/wasm_reference_abi.mjs:13](/home/dev/Projects/goose-wasm-backend/test/wasm_reference_abi.mjs:13). The preceding call at line 12 invokes `run()`. [scripts/run_wasm.mjs:133](/home/dev/Projects/goose-wasm-backend/scripts/run_wasm.mjs:133) clears `pending` and `snapshots` in an unconditional `finally` block. Thus every normal return to the assertion has `pendingPrints == 0`. Line 26 then writes a constant zero into the evidence record. The runner does not check `pendingSnapshots`.

   Trigger: a guest starts an extra print line, or creates an unused byte snapshot, and then returns without releasing that owner. If it emits the expected completed output first, the lost owner need not change output or guest memory. The adapter clears the owner before the new assertion can observe it. This is a confirmed property of the inspected control flow, not a reproduced guest failure. A runtime reproduction was prohibited for this review.

   Risk: the Node record can report successful guest cleanup when only host terminal cleanup removed the owner. It does not show a production compiler leak. The unchanged Wasmtime adapter checks both owner containers after `_start` and before any such clearing. Existing `wasm_bytes.mjs` controls also observe owners during guest output. Those controls reduce the risk, but do not validate this new Node assertion.

   Narrow correction: use a test completion hook or test adapter that reads both owner counts after `_start` returns and before terminal cleanup. Keep terminal cleanup. Add damaged controls that leave a print owner and a snapshot owner while preserving expected output. Each control must fail at the intended ownership assertion. Keep the memory-image comparison separate from this check.
